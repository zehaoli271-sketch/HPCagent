# 实时作业图

在仓库根目录运行：

```powershell
python -m pip install requests
python frontend/server.py
```

根据提示输入 JAccount 用户名和密码，在浏览器打开 http://127.0.0.1:8765/ 。服务只监听本机，密码和令牌只保存在运行进程中。也可使用 `HPC_USERNAME`、`HPC_PASSWORD` 环境变量，以及 `HPC_PROXY` 或 `--proxy` 配置代理；默认使用 127.0.0.1:7900。关闭终端或按 Ctrl+C 停止服务。

页面约每 10 秒查询一次本机服务，本机服务每个视图最多每 10 秒发起一次上游查询并复用登录令牌。上游采样频率、缓存和请求耗时决定实际新鲜度。失败时页面保留上次结果并显示查询时间。

最近完成视图展示最近五分钟内完成的作业，CPU 效率为整个作业的平均值。存在未核实的零值、资源分配、挂起或重启时显示暂无可信效率。运行中视图因累计 CPU 时间未验证而显示暂无可信效率；灰色斜纹不代表零效率。

## 给队友的计算接口

Python 代码可从仓库根目录导入 `from core.efficiency import calculate_job_efficiency`，传入 `/slurmdb/jobs` 返回的单个作业字典。返回 `efficiency`（0—1 或 null）、`cpu_seconds`（秒或 null）和 `reason`（说明或 null）。该函数当前保守排除有挂起的作业，因为分配容量是否保持不变尚未确认。

服务运行时也可向 `http://127.0.0.1:8765/api/v1/cpu-efficiency` 发送 POST，JSON 请求体直接传入单条 accounting 作业记录，返回上述三个字段。此接口只做计算，不向 HPC 发送数据。调用方负责只向本机服务提供已授权的数据。

方格数据接口为 `GET /api/v1/job-heatmap?view=completed` 或 `view=running`，包含查询时间、源更新时间（无则 null）和作业摘要。智能体诊断接口独立，现有接口草案仍待团队确认。
