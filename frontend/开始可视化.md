# 可视化工作从这里开始

先和队友阅读 `docs/接口约定.md`；它是 v1 提议，需双方确认。目前还没有后端接口或前端框架，示例数据在 `frontend/mock/`，全部为虚构数据。

第一版建议做单个作业诊断页面：上方输入作业 ID 和问题；结果区显示状态、资源和 CPU 效率；下方显示步骤表，以及事实、假设、数据缺口和建议。

三个必须能展示的状态：

1. `complete.json`：CPU 比值 0.25 显示为 25%；时间 3700 秒，挂起 100 秒，单任务 MaxRSS 标注单位。
2. `insufficient_data.json`：效率显示“数据不足”，不能显示成 0%；原始步骤 CPU 时间为 0 可以如实显示。
3. `error.json`：显示错误和重试提示，不显示上次作业的旧结果。

先根据这些状态画线框、确认信息层级，再决定页面框架。选择图表时，每个步骤是一行；`extern` 单独标明，不以单任务 MaxRSS 画出作业总内存占用。不要展示未验证的数值为确定结论。

在 VS Code 中从最新共享分支创建 `feature/visualization`，优先改 `frontend/`；每完成一小块就查看变动、运行本地验证、提交。需要改变 JSON 字段时先和队友在 PR 中讨论，并更新接口文档与 mock。

第一天可验收：能分别打开三种合成状态，解释 25% 从哪里来，说明 null 与 0 的区别。前端框架、启动命令和自动化测试在选择技术栈后补充；不要向仓库提交真实作业数据或凭据。
